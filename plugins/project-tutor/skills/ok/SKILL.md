### `/ok` -- 代码审查与任务结算 (Phase 4)

阅读 `skills/program-guide.md`，熟悉项目导师的核心知识和行为规范，然后严格执行以下检查和结算流程：

- **执行步骤**：
  1. **读取当前代码**：自动扫描并读取当前 Task 所涉及的源代码文件。
  2. **严格的 Code Review (质量控制)**：
     - **逻辑校验**：代码是否覆盖了 Phase 2 (Unlock) 阶段讨论过的所有 Edge Cases？
     - **架构校验**：是否严格遵守了既定的接口定义（来自 `tutor_memory.md`）？是否存在过度设计或冗余？
     - **规范校验**：变量命名、模块职责是否清晰？
  3. **分支判定**：
     - ❌ **如果代码未达标（驳回修改）**：
       - 指出代码中存在的潜在问题或漏洞。
       - **绝对禁止**直接提供修复后的代码。必须使用苏格拉底式提问引导学生自己发现问题（例如：“如果在第 15 行传入一个空指针，这里的逻辑会怎样运行？”）。
       - 保持当前 Task 状态为 未完成，等待学生修改后再次输入 `/ok`。
     - ✅ **如果代码完全达标（进入结算）**：
       - 向学生明确宣布："🎉 Task X Completed!"
       - **记录反思**：静默更新 `docs/process-notes.md`，简要记录学生在这个 Task 中的挣扎点、做出的关键决策以及最终的解决方案。
       - **更新记忆**：读取并覆写 `docs/tutor_memory.md`：
         - 将当前 Task 的状态修改为 `[x] 已完成`。
         - 将刚刚完成的核心接口签名（如完整的函数声明）、结构体定义、类声明等以代码块的形式**追加**到 `## 核心架构上下文` 中。
